# Анализ удержания пользователей (Retention & Rolling Retention)

## 📋 Описание задачи

Данный SQL-запрос предназначен для анализа удержания пользователей (cohort analysis) на основе данных о входах пользователей. Запрос рассчитывает два типа метрик:

1. **Retention (классическое удержание)** — процент пользователей, вернувшихся в конкретный день (3, 5, 7, 14, 21, 30, 60, 90 день)
2. **Rolling Retention (накопительное удержание)** — процент пользователей, вернувшихся хотя бы один раз за период (начиная с указанного дня)

---

## 🗄️ Структура данных

| Таблица | Поле | Описание |
|---------|------|----------|
| **`users`** | `id` | Уникальный идентификатор пользователя |
| | `date_joined` | Дата регистрации пользователя |
| **`userentry`** | `user_id` | Идентификатор пользователя (внешний ключ) |
| | `entry_at` | Дата и время входа в систему |

---

## 💻 SQL-запрос

```sql
with retention as (
	select 
		u.user_id, 		
		extract(days from u.entry_at - u2.date_joined) as diff,
		to_char(u2.date_joined, 'YYYY-MM') as cohort
	from userentry u 
	join users u2 
	on u2.id = u.user_id 
	where to_char(u2.date_joined, 'YYYY') = '2022'
)
select 
	cohort,
	round(count(distinct case when diff = 0 then user_id end) * 100.0 / count(distinct case when diff = 0 then user_id end)) as "0 %",
	round(count(distinct case when diff = 3 then user_id end) * 100.0 / count(distinct case when diff = 0 then user_id end), 2) as "3 (%)",
	round(count(distinct case when diff = 5 then user_id end) * 100.0 / count(distinct case when diff = 0 then user_id end), 2) as "5 (%)",
	round(count(distinct case when diff = 7 then user_id end) * 100.0 / count(distinct case when diff = 0 then user_id end), 2) as "7 (%)",
	round(count(distinct case when diff = 14 then user_id end) * 100.0 / count(distinct case when diff = 0 then user_id end), 2) as "14 (%)",
	round(count(distinct case when diff = 21 then user_id end) * 100.0 / count(distinct case when diff = 0 then user_id end), 2) as "21 (%)",
	round(count(distinct case when diff = 30 then user_id end) * 100.0 / count(distinct case when diff = 0 then user_id end), 2) as "30 (%)",
	round(count(distinct case when diff = 60 then user_id end) * 100.0 / count(distinct case when diff = 0 then user_id end), 2) as "60 (%)",
	round(count(distinct case when diff = 90 then user_id end) * 100.0 / count(distinct case when diff = 0 then user_id end), 2) as "90 (%)",
	max('retention') as "cohort_analys"
from retention
group by cohort
union all
select 
	cohort,
	round(count(distinct case when diff >= 0 then user_id end) * 100.0 / count(distinct case when diff >= 0 then user_id end)) as "0 %",
	round(count(distinct case when diff >= 3 then user_id end) * 100.0 / count(distinct case when diff >= 0 then user_id end), 2) as "3 (%)",
	round(count(distinct case when diff >= 5 then user_id end) * 100.0 / count(distinct case when diff >= 0 then user_id end), 2) as "5 (%)",
	round(count(distinct case when diff >= 7 then user_id end) * 100.0 / count(distinct case when diff >= 0 then user_id end), 2) as "7 (%)",
	round(count(distinct case when diff >= 14 then user_id end) * 100.0 / count(distinct case when diff >= 0 then user_id end), 2) as "14 (%)",
	round(count(distinct case when diff >= 21 then user_id end) * 100.0 / count(distinct case when diff >= 0 then user_id end), 2) as "21 (%)",
	round(count(distinct case when diff >= 30 then user_id end) * 100.0 / count(distinct case when diff >= 0 then user_id end), 2) as "30 (%)",
	round(count(distinct case when diff >= 60 then user_id end) * 100.0 / count(distinct case when diff >= 0 then user_id end), 2) as "60 (%)",
	round(count(distinct case when diff >= 90 then user_id end) * 100.0 / count(distinct case when diff >= 0 then user_id end), 2) as "90 (%)",
	max('rolling_retention')
from retention
group by cohort;
```

## 🔍 Логика работы запроса

### Шаг 1: Подготовка данных (CTE `retention`)

```sql
with retention as (
    select 
        u.user_id, 		
        extract(days from u.entry_at - u2.date_joined) as diff,
        to_char(u2.date_joined, 'YYYY-MM') as cohort
    from userentry u 
    join users u2 on u2.id = u.user_id 
    where to_char(u2.date_joined, 'YYYY') = '2022'
)
```

**Что происходит:**
- Вычисляется разница в днях между входом пользователя и датой его регистрации (`diff`)
- Формируется когорта по месяцу регистрации (`cohort`)
- Фильтрация пользователей, зарегистрированных в 2022 году

---

### Шаг 2: Расчет классического Retention

**Формула:**
```
Retention (день N) = (Количество пользователей с diff = N) / (Количество пользователей с diff = 0) × 100%
```

**Пример для 3-го дня:**
```sql
round(count(distinct case when diff = 3 then user_id end) * 100.0 / 
      count(distinct case when diff = 0 then user_id end), 2) as "3 (%)"
```

**Что означает:**
- `diff = 0` — пользователи, активные в день регистрации (база для расчета)
- `diff = 3` — пользователи, вернувшиеся на 3-й день
- Результат — процент пользователей, вернувшихся на 3-й день

---

### Шаг 3: Расчет Rolling Retention

**Формула:**
```
Rolling Retention (день N) = (Количество пользователей с diff >= N) / (Количество пользователей с diff >= 0) × 100%
```

**Пример для 3-го дня:**
```sql
round(count(distinct case when diff >= 3 then user_id end) * 100.0 / 
      count(distinct case when diff >= 0 then user_id end), 2) as "3 (%)"
```

**Что означает:**
- `diff >= 0` — все пользователи когорты
- `diff >= 3` — пользователи, вернувшиеся хотя бы раз начиная с 3-го дня
- Результат — процент пользователей, вернувшихся хотя бы раз за период от 3-го дня

---

### Шаг 4: Объединение результатов

Используется `UNION ALL` для объединения двух типов анализа:
- **Первая часть запроса** — классический Retention (метка `'retention'`)
- **Вторая часть запроса** — Rolling Retention (метка `'rolling_retention'`)

## 🎯 Ключевые выводы

### 📌 Основные наблюдения

1. **Лучшая когорта:** 2022-01 показывает наилучшие результаты как по классическому, так и по накопительному удержанию во всех периодах

2. **Худшая когорта:** 2022-02 демонстрирует самые низкие показатели удержания

3. **Критические точки падения:**
   - 🔴 **Дни 3-7** — наиболее интенсивная потеря пользователей (первая волна оттока)
   - 🟡 **Дни 14-21** — вторая волна оттока пользователей
   - 🟢 **Дни 30+** — постепенное снижение с замедлением

4. **Разница между Retention и Rolling Retention:**
   - Rolling Retention значительно выше классического (в 3-4 раза на ранних периодах)
   - Разница особенно заметна на поздних периодах (30-90 дней)

5. **Аномалии в данных:**
   - Когорта 2022-04 показывает нелогичный рост retention на 7-й день (7.39% против 5.91% на 5-й день)
   - Требуется проверка данных на возможные ошибки

6. **Сезонность:**
   - Январская когорта — наилучшая
   - Февральская когорта — наихудшая
   - Возможно влияние новогодних праздников и сезонных акций
